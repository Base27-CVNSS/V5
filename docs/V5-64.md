# Experimental V5-64 address schema (version 1)

**Status:** Implemented canonical path packing and example planar path decoding; **NOT** an operational global geographic index.

The V5 research address has four fixed fields:

| Bit positions | Width | Meaning |
| --- | ---: | --- |
| 63..60 | 4 | Nonzero version, currently 1 |
| 59..56 | 4 | Resolution 0–10 |
| 55..50 | 6 | Root face 0–11 |
| 49..0 | 50 | Ten 5-bit base-32 child digits, left aligned |

Unused low-order path slots **must be zero**; the decoder rejects noncanonical values. Root pentagons are currently *labels*, not assigned global WGS84 orientation geometry. The planar example is independent of global root numbering.

## Reference implementation

```python
from src.v5id import encode, decode, parent, children, geometry_in_example_root
root = encode(0)
kids = children(root)
assert len(kids) == 32
assert all(parent(k) == root for k in kids)
assert decode(kids[31]).path == (31,)
poly = geometry_in_example_root(kids[31])
assert len(poly) == 5
```

`geometry_in_example_root` uses each digit's five high-to-low binary bits to follow the five consecutive splits in `src/v5.py`. This is **strict geometric containment in an arbitrary sample root face**, not a GPS cell locator. A conforming globe embedding, neighbor graph, and projection are separate unresolved developments.

**Research caution:** The number five in five-bit base-32 digits is an encoding choice, not a proof that five-sided cells are computationally faster than hexagons. H3 also uses 64-bit cell IDs, but its geometric hierarchy and semantics differ.
